# Newsletter & alert prompt

The public opt-in prompt is managed in **Admin → Website → Newsletter & alerts prompt**. It ships enabled for a **10% pilot** across the home page and the send/errand task pages; adjust or disable it at any time from that card.

## Subscriber flow

1. A visitor triggers the prompt by idle time, high engagement, exit intent, or abandoning a started send/errand task.
2. They see an email-first one-field form. The button label is the configured main CTA, or the lead-magnet CTA when one is configured.
3. Clicking the CTA is the affirmative consent action; the disclosure is shown directly beside the button. No channel dropdown, interest checkboxes or consent checkbox are shown by default.
4. A confirmation link/code is sent through the selected channel.
5. Only confirmed subscribers are considered subscribed. The prompt then stays suppressed for that visitor.
6. Every subscriber can unsubscribe with the signed link generated by the app.

Parcel tracking notifications are separate and are not marketing consent.

## Artwork

The admin card accepts PNG, JPG or WebP artwork between 300 x 160 and 3000 x 3000 pixels, up to 2 MB. Uploaded artwork is stored under `/assets/img/newsletter/` and is used:

- in the public prompt;
- in the newsletter confirmation email;
- as the configuration source for future newsletter sends.

Artwork can be replaced or removed from the card at any time.

## Admin controls

- Enable/disable the prompt
- Pilot traffic percentage
- Allowed paths (`/` for home; task pages can be added)
- Channels: Email, SMS, WhatsApp (a channel must also be active in **Admin → Communications** before it appears publicly)
- Idle, active and abandoned-task trigger thresholds
- Frequency and dismissal suppression
- Prompt artwork upload/preview/remove
- Title, body, CTA, dismissal and consent copy
- Live preview
- Subscriber counts and recent sign-ups
- CSV export: `/api/admin-newsletter-export.php`

## Data

`newsletter_subscribers` stores contact, channel, interests, consent version, status, source/trigger, confirmation token hash and timestamps. Stored values are sanitized and confirmation tokens are hashed.

- Statuses: `pending`, `confirmed`, `unsubscribed`
- Confirmation expiry: 48 hours
- Consent checkbox is unchecked by default
- Marketing preference is updated for linked signed-in accounts after confirmation

## Low-friction form

- Email-first default when email is active.
- If SMS/WhatsApp is also active, a small “Prefer SMS/WhatsApp?” text link switches the field to phone; no dropdown.
- Newsletter and product alerts are combined in the subscription; preferences are managed after confirmation.
- Consent is affirmative button action with disclosure beside the CTA and a Privacy Policy link. Double opt-in is still required.
- Optional lead magnet: set a URL and button label in admin. The prompt uses that CTA, and confirmed subscribers receive the lead-magnet link on the confirmation page and in the confirmation email.

## Channels

Email is active in the current demo. SMS and WhatsApp are supported by the same flow but require an active provider and sender ID in **Admin → Communications**. Inactive channels appear in the admin card with an “inactive” note and are not offered to visitors until activated.

## Operations

- Review subscriber counts and export weekly.
- Do not send marketing email/SMS without an unsubscribe link and the subscriber’s consent.
- Keep `consent_version` aligned with the Privacy Policy text.
- If copy or trigger settings change, monitor dismissal and confirmation rates.
- The prompt never appears in authenticated app areas; it targets public pages only.
